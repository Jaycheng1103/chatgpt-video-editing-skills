## 第 1 步之前｜自動檢查環境（只檢查，不改任何東西）

開始前先檢查：

1. 作業系統、CPU 架構與目前使用的 Agent。
2. Git、Python、uv、FFmpeg、ffprobe、Node.js（22 以上）、npx 是否存在，FFmpeg 能否解碼 VP9 透明影片（`libvpx-vp9`）；只檢查，不要自行安裝。
3. `~/Developer/video-use` 是否存在；`npx --no-install hyperframes@0.9.86 skills check --json` 的 HyperFrames 技能是否齊全、是否最新；`npx --no-install hyperframes@0.9.86 browser path` 能否找到 HyperFrames 的渲染瀏覽器。
4. 適用的既有 Repo 是否為 Git worktree，以及 exact origin、目前 branch 或 detached 狀態、commit 與工作目錄狀態。
5. Agent 的 Skills 目錄與現有 `video-use` 註冊狀態。
6. 字幕字體：macOS 檢查 `~/Library/Fonts`、Linux 檢查 `~/.local/share/fonts` 是否已有 `SourceHanSansTW-Regular.otf` 與 `SourceHanSansTW-Bold.otf`，且為一般檔案而非 symlink；有 `fc-list` 時一併確認能否列出 Source Han Sans TW。只檢查，不下載。
7. ElevenLabs 憑證來源是否存在，但不可顯示、讀取或推測憑證內容。

只接受以下精確的官方 HTTPS origin，不自動改寫 remote：

- video-use：`https://github.com/browser-use/video-use.git`
- HyperFrames：npm 套件 `hyperframes`，固定 `0.9.86` 版（官方 Repo：<https://github.com/heygen-com/hyperframes>），不需要 Clone 原始碼。

不要用 `$repo/.git` 是否為目錄來判斷 Repo，因為 linked worktree 的 `.git` 是檔案。對 video-use 執行以下檢查：

```sh
inspect_repo() {
  repo=$1
  expected_origin=$2
  if [ ! -e "$repo" ] && [ ! -L "$repo" ]; then
    printf '%s\n' "missing repository: $repo"
    return 2
  fi
  inside=$(git -C "$repo" rev-parse --is-inside-work-tree 2>/dev/null) || return 1
  [ "$inside" = true ] || return 1
  commit=$(git -C "$repo" rev-parse --verify HEAD) || return 1
  branch=$(git -C "$repo" branch --show-current) || return 1
  [ -n "$branch" ] || branch="(detached at $commit)"
  actual_origin=$(git -C "$repo" remote get-url origin) || return 1
  [ "$actual_origin" = "$expected_origin" ] || {
    printf '%s\n' "STOP: unexpected origin for $repo: $actual_origin" >&2
    return 1
  }
  status=$(git -C "$repo" status --short) || return 1
  printf '%s\n' "repo=$repo" "origin=$actual_origin" \
    "branch=$branch" "commit=$commit" "status=${status:-clean}"
  [ -z "$status" ] || return 3
}
```

回傳 `3` 代表官方 Repo 但有改到一半的修改：不要停下，列進第 2 步清單，核准後先完整備份再更新成官方最新版（做法見第 2 步）。`helpers/render.py` 沒有 `--no-subtitles` 的舊版也一樣處理。

既有路徑若不是 Git worktree、沒有 origin、origin 不精確相符或 commit 無效，就是 hard stop。立即停止對該 Repo 的 pull、reset、覆寫、重新 Clone、依賴安裝、Skill 註冊或其他修改；回報路徑與證據，等我決定安全處理方式。即使 Repo 很乾淨，錯誤 origin 也不能繼續，更不能自動改成官方 URL。

檢查完後，每一步先把要做的變更（Clone Repo、安裝套件、下載字體、建立 symlink、加入 MCP、建立憑證檔等）整理成一張白話清單，附位置與大約大小，問我一次「要一次幫你裝好嗎？」。我說好之後，清單上的項目就一次做完；清單以外、後來才發現的變更要另外問。核准等待期間 Git 狀態可能改變，因此每次依賴安裝或 Skill 註冊前，都要重跑適用的 `inspect_repo`，重新確認 exact origin、branch／commit 與乾淨狀態。

## 第 2 步｜字幕字體（思源黑體 TW）

官方 Repo：<https://github.com/adobe-fonts/source-han-sans>（SIL Open Font License 1.1）

繁體中文字幕燒錄預設使用思源黑體 TW（Source Han Sans TW）；缺少合適的 CJK 字體時，燒錄結果可能出現豆腐字或退回不合適的系統字體。只接受官方 Repo 的 `release` 分支作為下載來源，不可使用鏡像站、字體整理站或名稱相似的 Repo，也不可默默改用其他字體。

若前面的環境檢查已確認兩個字重都是一般檔案，回報已存在並跳過這一段；不可重新下載或覆寫既有字體檔。若字體路徑存在但是 symlink、資料夾或其他非一般檔案，停止並回報，不可取代。

缺少字重時，先把下載列為待核准項目（每個字重約 6 MB，預設兩個字重）。核准後執行：

```sh
case "$(uname -s)" in
  Darwin) font_dir="$HOME/Library/Fonts" ;;
  Linux) font_dir="$HOME/.local/share/fonts" ;;
  *) printf '%s\n' 'STOP: unsupported platform; install the font manually.' >&2; exit 1 ;;
esac
font_source=https://github.com/adobe-fonts/source-han-sans/raw/release/SubsetOTF/TW
mkdir -p "$font_dir"
for weight in Regular Bold; do
  font_file="$font_dir/SourceHanSansTW-$weight.otf"
  if [ -e "$font_file" ] || [ -L "$font_file" ]; then
    printf '%s\n' "skip existing path: $font_file"
    continue
  fi
  curl -fL --proto '=https' -o "$font_file" \
    "$font_source/SourceHanSansTW-$weight.otf"
done
if [ "$(uname -s)" = Linux ]; then
  command -v fc-cache >/dev/null 2>&1 && fc-cache -f "$font_dir"
fi
```

回報安裝完成前，必須驗證每個檔案是真正的 OpenType/CFF 字體，`SourceHanSansTW-Regular.otf` 與 `SourceHanSansTW-Bold.otf` 都要以 `OTTO` magic bytes 開頭：

```sh
for weight in Regular Bold; do
  font_file="$font_dir/SourceHanSansTW-$weight.otf"
  [ -f "$font_file" ] && [ ! -L "$font_file" ] || exit 1
  magic=$(head -c 4 "$font_file" | od -An -tx1 | tr -d ' \n') || exit 1
  [ "$magic" = 4f54544f ] || {
    printf '%s\n' "STOP: not a valid OpenType font: $font_file" >&2
    exit 1
  }
done
```

下載失敗或驗證停止時，不可自動刪除任何檔案；回報精確路徑與證據，等我決定。若我需要其他字重、其他地區子集、Super OTC 或可變字型，另列核准項目，並依上游官方 `SourceHanSansReadMe.pdf` 的 Configurations 說明選擇。

## 第 2 步｜ElevenLabs API 金鑰（逐字時間碼用）

ElevenLabs MCP 負責串接帳號；剪輯需要每個字的時間碼，所以逐字稿用 Scribe v2 API 金鑰。金鑰由我自己貼進你幫我打開的檔案，不貼在聊天室。

ElevenLabs Scribe v2 用於完整精度流程的 word-level 逐字時間碼。只允許下列憑證來源：

1. 本機 process environment 中的 `ELEVENLABS_API_KEY`。
2. 受保護的 `~/Developer/video-use/.env`。

絕對不要要求我把 API Key 貼進聊天、命令列參數、公開檔案、commit、shell history 或 log，也不要輸出憑證的值、長度、開頭、結尾或看似遮罩的替代字串。

若環境變數不存在，而且需要使用 `.env`，必須先取得我對本機憑證檔變更的核准，並在要求我寫入任何內容之前執行：

```sh
git -C "$HOME/Developer/video-use" check-ignore -q .env
```

若 `.env` 尚未被忽略，不可建立檔案，也不可要求我提供金鑰。優先改用環境變數；或在我另外核准後，只把精確的 `.env` 規則加入 Git 解析出的 Repo 本機 exclude 檔，再重跑 ignore 檢查。不要猜測 `$repo/.git/info/exclude`，因為 linked worktree 的路徑不同：

```sh
repo="$HOME/Developer/video-use"
exclude=$(git -C "$repo" rev-parse --path-format=absolute --git-path info/exclude) || exit 1
case "$exclude" in /*) ;; *) exit 1 ;; esac
[ -f "$exclude" ] && [ ! -L "$exclude" ] || exit 1
grep -qxF '.env' "$exclude" || printf '%s\n' '.env' >> "$exclude"
git -C "$repo" check-ignore -q .env
```

如果目前 Git 不支援 `--path-format=absolute`、結果不是絕對路徑，或解析出的 exclude 不是可驗證的一般非 symlink 檔案，立即停止並改提環境變數方案，不可猜路徑。

只有 ignore 檢查成功後，才請我透過對話外的安全本機編輯器或終端機自行寫入。Agent 不讀取檔案內容。等我確認檔案存在後，先拒絕 symlink、資料夾或其他非一般檔案，再調整與驗證權限。macOS 使用 BSD `stat`，Linux 使用 GNU `stat`，不支援的平台要如實停止：

```sh
env_file="$HOME/Developer/video-use/.env"
[ -f "$env_file" ] && [ ! -L "$env_file" ] || exit 1
chmod 600 "$env_file"
case "$(uname -s)" in
  Darwin) mode=$(stat -f '%Lp' "$env_file") ;;
  Linux) mode=$(stat -c '%a' "$env_file") ;;
  *) printf '%s\n' 'STOP: unsupported platform; .env mode was not verified.' >&2; exit 1 ;;
esac
[ "$mode" = 600 ] || exit 1
```

設定階段只確認核准的憑證來源存在，以及 `.env` 的 ignore 狀態與權限；不要上傳測試音檔、呼叫轉寫、查詢雲端額度或以付費請求驗證。

第一次真正上傳媒體前，必須另外說明具體檔名、上傳目的是使用 ElevenLabs Scribe v2 取得逐字時間碼，以及可能消耗 API 額度或產生費用。等待我對這一次上傳明確同意後才能執行。

## 第 3 步｜放入想要剪輯的影片

請我把影片拖進來或給路徑。所有新產物放在原始影片同層的 `edit/`；不可覆寫、搬移、重新命名或刪除原始影片。若 `edit/project.md` 已存在，先讀取並記錄本次工作階段。

使用 ffprobe 檢查影片／音訊 streams、長度、方向、解析度、幀率、旋轉資訊、取樣率、色彩標籤與完整可解碼性，再建立 `edit/`。用白話告訴我這支影片的狀況，然後問我是否同意把聲音上傳到 ElevenLabs 轉逐字稿，並說明會用到我帳號的額度。

## 第 4 步｜取得剪輯建議並用 ElevenLabs 拿到逐字稿

取得這個檔案的上傳同意後，用 ElevenLabs Scribe v2 產生逐字原文與 word-level timestamps，依未變更的來源快取；來源沒變就不要重跑。若我拒絕雲端上傳，先說明本機 Whisper 是時間碼信心較低的降級方案，問我是否明確選用；選用後把逐字稿標為 lower-confidence，並對每個剪接邊界加做播放檢查。

把逐字稿整理成有編號與起始時間的段落（①②③…），只修明顯的辨識錯字並標出來；人名、書名、數字與專有名詞無法確認時列為待確認，不要猜。每段標出屬於五段腳本的哪一段：鉤子（為什麼我該在意，含憑什麼那句）、背景、挑戰、行動、收穫；我有腳本時會一起貼上，照腳本標，但不可把沒講出口的台詞加進去。接著用 4～8 句白話給我剪輯建議：觀眾看完得到什麼、開頭用哪一句當鉤子、五段是否齊全（缺哪段就建議補拍一句，不要編）、建議刪哪幾段與原因、預計長度、字幕方式，以及是否提議圖卡、B-roll、動畫、配樂、音效或 CTA。

## 第 5 步｜詢問我是否刪減逐字稿

問我要刪哪幾段（附你的建議）。只做刪減與換位置，不改寫我說過的話，也不扭曲原意、時間順序或因果關係。刪完列出剩下的段落和新的預估長度。我確認的保留清單就是核准的策略；在此之前不可決定剪接點，也不可自行加入 B-roll、動畫、音效、音樂、CTA 或發布排程。

## 第 6 步｜參考剪輯風格

請我貼一支喜歡的 IG、TikTok、YouTube Shorts 或 X 短影音連結。用 Agent Reach 讀貼文資訊，用 `yt-dlp`（或 `uvx yt-dlp`）下載到 `edit/reference/`；Instagram 或 X 需要登入而抓不到時，請我把影片存下來拖進來，不要自己讀取我瀏覽器的登入資料。

用 ffprobe 量長度，用 ffmpeg 場景偵測估算平均幾秒換一個畫面，擷取數張畫面觀察字幕位置、字級、顏色、外框、重點字樣式、推近、B-roll、圖卡與開頭 3 秒的做法，寫成 `edit/style/style-recipe.md`。用白話跟我確認，並說明哪些不會照抄（對方的畫面、音樂、標誌、浮水印與文字一律不放進成片）。沒有參考影片時，用乾淨口播風格。

## 第 7 步｜剪輯出品

以 word-aligned kept ranges 建立 `edl.json`，每個範圍保留來源、start、end、beat、quote 與 reason，並保持來源區間和輸出 offset 一致。

- 不可切進字詞內或切掉字頭、字尾；依口語節奏在完整字詞邊界外保留 30–200ms。
- 每個保留段落獨立擷取、處理與驗證，再接合；每段音訊邊界加入約 30ms 淡入淡出。
- 調色或 HLG-to-Rec.709 校正只在技術上需要或我已核准時執行。
- 套用風格配方。用 video-use 渲染時加 `--no-subtitles`，不用它內建的字幕。
- 字幕：字卡時間依輸出時間軸計算（`output_time = word.start - segment_start + segment_offset`）。一張字卡只有一行，每行最多 8 個字（中文算 1，英數算 0.5），超過就變成下一句字幕，不可出現兩、三行；斷在詞與詞之間，不切開詞、英文單字或數字；標點不顯示；簡體逐字稿轉成台灣繁體。字幕用思源黑體 TW Bold，放在避開人物臉部與平台 UI 的字幕帶；字體缺少時回到第 2 步，不可默默換字體。
- CSS 特效：用 HyperFrames 讓畫面活潑但不炫技。字幕彈入、重點字變色；講到核心觀念跳出大字重點，講「第一、第二」滑入步驟標籤，連續列舉出現打勾清單，語氣加重時畫面推近。特效跟著講話內容出現、一次只出現一個、不遮臉也不遮正在示範的畫面；動態一律用有加減速的曲線，不用等速。
- 合成順序：剪好的影片（含推近）→ 特效層 → 字幕在最上層。
- 保留清楚自然的人聲，只加入已核准的音樂與效果。

先輸出一支完整 720p 預覽，檢查實際渲染結果：每個剪接點前後 ±1.5 秒的跳畫面、閃幀、爆音、同步、字幕與疊圖，片頭、片尾、中段代表畫面、字幕安全區、色彩、混音、streams、長度、尺寸與完整解碼。只有證據指出明確問題時才自動修正，最多三輪。然後把預覽給我，問我要改哪裡或可以輸出正式版。

只有我明確核准 720p 預覽後，才渲染一支 1080×1920 的正式 `final.mp4`，並針對正式檔本身重新檢查剪接邊界、代表畫面與完整解碼。順序必須是：預覽 QA → 我核准預覽 → 渲染正式檔 → 驗證正式檔 → 交付。交付後問我要不要用同樣風格剪下一支。
